# ADR-001：BLAS / Metal 驱动的基础设施例外

- 状态：已接受
- 日期：2026-11-26
- 决策人：项目所有者
- 关联：`docs/00-边界说明书.md` §3.2

## 背景

边界说明书要求执行层也自研，包括张量、算子、梯度和内核。但矩阵乘的底层实现依赖 CPU 的 BLAS 库（Apple Accelerate）与 GPU 的 Metal 驱动/编译器。若连这些也要求自研，需要重写线性代数库与图形驱动，L 层吞吐会下降两个数量级以上，项目不可行。

## 决策

以下内容视为**硬件基础设施**，允许调用：

1. NumPy 的内存块、索引、形状操作、逐元素运算。
2. BLAS（经 NumPy 或 Accelerate）提供的矩阵乘底层。
3. Metal 驱动、Metal 编译器、macOS 系统框架。

以下内容**必须自研**，不得调用现成实现：

1. Tensor 类、计算图、反向传播、梯度累积。
2. 算子组合与调度（Linear、Softmax、LayerNorm、Attention、Adam 等）。
3. Metal 着色器（kernel）与训练循环。
4. 课程、评估、checkpoint、日志。

## 理由

- 自研的目标是“不借用现成智能实现”，不是“重新发明浮点乘法”。
- BLAS/Metal 驱动等价于 CPU 指令集：属于执行介质，不属于智能机制。
- 保持这条边界，才能把工程量集中在架构、学习规则与内核调度上。

## 边界与禁止

- 不得调用任何现成神经网络算子（如 `torch.nn.Linear`、`jax.lax.conv`）。
- 不得调用任何自动微分库。
- 不得把 BLAS 调用包装成“自研算子”对外宣称；报告中必须声明该例外。
- 任何扩大解释（例如允许调用 cuBLAS 的神经网络封装）需单独 ADR。

## 复核

每月复核一次；若发现 BLAS 调用已实质承担智能机制（如直接调用现成 Attention），立即回退并记录。
