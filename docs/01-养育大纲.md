# 玖白（Chiubay）养育大纲

> 依据：`docs/00-边界说明书.md` v0.2
> 版本：v0.1 | 2026-11-26
> 本大纲回答“怎么养”，不回答“怎么建仓库”。所有排期为计划，不是承诺。
> 诚实前提：单人、单机、全栈自研，天花板约 1B 参数；本项目不宣称达成 AGI。

---

## 0. 养育哲学

### 0.1 三句话

1. **孩子不是产品**：不追 demo、不追榜单，只追“机制是否成立”。
2. **长大不等于变强**：参数变大、分数变高，都不等于更通用；要看迁移与自主性。
3. **父母会退场**：父母的作用是搭脚手架，不是替孩子思考；比例必须逐阶段下降。

### 0.2 成功的定义

- S0-S2 机制成立，且可复现、可审计、可证伪。
- 失败案例完整保留，不删日志、不改指标。
- 报告能说清“哪里不行”，而不是只展示“哪里行”。

### 0.3 失败的定义

- 指标造假、选择性汇报。
- 偷偷加载预训练权重或蒸馏。
- 用提示词、API 父母或人工规则冒充孩子能力。
- 把“小模型 + 大词表”包装成 AGI。

## 1. 孩子的天生条件

### 1.1 架构基底

```text
感官输入 → 自研编码器 → 自研 recurrent（S2 起）→ LSE × N → 自研解码器 → 动作/词
```

- LSE：专家 + 门控 + 联动桥；分裂/合并接口预留，S5 才启用。
- recurrent：自研门控方程，不调用现成 RNN/LSTM 实现。
- 执行层：自研张量、算子、梯度、优化器；S 层移植到自写 Metal 内核。

### 1.2 初始状态

- 所有权重随机初始化，无任何先验。
- 词表、动作空间、感官归一化参数由环境定义，不属于“知识”。
- 每个实验固定 seed；同 seed 必须可复现趋势。

### 1.3 感官与动作预算

| 阶段 | 视觉 | 语言 | 动作 | 参数量 |
|---|---|---|---|---|
| S0 | 16 维状态向量 | 无 | 5 离散（上下左右+交互） | <1M |
| S1 | 64×64 RGB，自研卷积编码 | 无 | 5 离散 + 抓取 | <5M |
| S2 | 同 S1 | 50-200 词自建词表 | 同 S1 | <10M |
| S3 | 同 S1 | 同 S2 | 加“等待/示意” | 10M-100M |
| S4 | 同 S1 | 同 S2 | 同 S3 | 100M-1B |
| S5 | 同 S1 | 同 S2 | 同 S3 | 100M-1B |

### 1.4 天生缺陷（必须承认）

- 没有长时记忆：S2 前只能靠 recurrent 的短窗口。
- 没有世界模型：S1 起才逐步建立物体恒存。
- 没有身体：所有“行动”都是离散符号，不是真实物理。
- 没有社会本能：S3 才开始学他者。
- 这些缺陷不是 bug，是发育顺序；不要用“加模块”跳过阶段。

## 2. 父母是谁

### 2.1 三角色

| 角色 | 由谁扮演 | 做什么 | 不做什么 |
|---|---|---|---|
| 教师 T | API 大模型 | 设计课程、生成示范、用自然语言描述场景 | 不直接改孩子权重、不注入答案 |
| 评估 E | API 大模型 + 规则 | 给标量奖励、检测异常、写评估报告 | 不参与训练梯度、不替代环境奖励 |
| 监护 G | 规则引擎 + 人工 | 审批架构修改、执行 kill switch、回滚 | 不替孩子做任务 |

### 2.2 父母共识

- 重大决定（进入下一阶段、架构扩展）需：T 置信度 >0.8 **且** E 奖励提升 >10%。
- G 有一票否决权；否决必须写审计日志。
- 父母之间冲突时，以“安全 > 可复现 > 能力提升”排序。

### 2.3 父母退场表

| 阶段 | 父母介入比例 | 形式 |
|---|---|---|
| S0 | 30% | 规则奖励 + 20 条示范 |
| S1 | 25% | 联合注意示范 + 属性课程 |
| S2 | 20% | 指令生成 + 示范 |
| S3 | 15% | 扮演同伴 + 社会反馈 |
| S4 | 10% | 课程建议 + 复习计划 |
| S5 | 5% | 只做安全审批与边界守护 |

退场不是消失，是降低频率；S5 之后父母主要是“监护人”，不是“老师”。

### 2.4 成本与可复现

- 月预算上限 $50；超支停实验。
- 固定模型 snapshot、温度、prompt 版本；换版本必须重跑基线。
- prompt hash 缓存，命中率目标 >60%。
- 所有调用写 `runs/<exp>/parents_log.jsonl`。

## 3. 家庭环境

### 3.1 房间（课程环境）

| 房间 | 阶段 | 内容 | 可调参数 |
|---|---|---|---|
| 网格房 | S0 | 8×8 / 16×16 网格、目标、障碍、可推物体 | 地图大小、障碍率、目标数 |
| 属性房 | S1 | 3 色 × 3 形 × 1-3 物体、遮挡、藏找 | 颜色/形状组合、遮挡率 |
| 语言房 | S2 | 指令模板、指称游戏、干扰物 | 指令长度、组合数、干扰数 |
| 社交房 | S3 | 双人网格、共同目标、轮流 | 同伴策略、沟通通道 |
| 开放房 | S4-S5 | 程序生成任务、目标自拟 | 任务族、难度曲线 |

### 3.2 安全边界

- 无网络：Child 进程不能发起任何外部连接；父母调用走独立代理进程。
- 无文件：Child 只能读写自己的 checkpoint 目录。
- 无外部进程：禁止 `subprocess`、`os.system`。
- kill switch：检测到越界立即终止并回滚到最近安全 checkpoint。
- 沙盒实现：独立进程 + 权限隔离；S 层再评估是否加容器。

### 3.3 课程空间

- 每个房间必须有：任务生成器、成功判定、难度参数、反事实变体。
- 难度按“最近发展区”调：成功率低于 50% 降难度，高于 85% 升难度。
- 反事实变体必须与训练集分离，防止死记硬背。

## 4. 发育阶段

### S0 感知运动（0-4 月）

| 项 | 内容 |
|---|---|
| 目标 | 从随机策略学会目标导向；专家开始分化 |
| 环境 | 8×8 网格，1 目标，0-3 障碍，1 可推物体 |
| 课程 | 固定地图 → 随机地图 → 有障碍 → 推物到目标 |
| 父母 | E 规则奖励塑形；T 给 20 条示范；G 只监控 |
| 评估 | G0 全部指标 |
| 退场 | G0 通过 |
| 常见失败 | 全选一个专家；熵崩溃；原地打转；奖励黑客 |

### S1 概念形成（4-8 月）

| 项 | 内容 |
|---|---|
| 目标 | 颜色/形状/物体恒存；多模态关联；专家可解释 |
| 环境 | 64×64 RGB，3 色 × 3 形，1-3 物体，遮挡与藏找 |
| 课程 | 指认 → 配对 → 按属性取物 → 藏找 |
| 父母 | T 联合注意示范（指+命名）；E 属性奖励；G 监控 |
| 评估 | 新物体迁移 >70%；专家激活热力图出现属性选择性 |
| 退场 | 迁移达标 + 至少 2 类“属性专家” |
| 常见失败 | 只记位置不记属性；颜色/形状混淆；专家全响应同一特征 |

### S2 语言与指令（8-14 月）

| 项 | 内容 |
|---|---|
| 目标 | 序列建模；符号接地；理解未见组合 |
| 环境 | 语言房；自建 50-200 词表；1-3 步指令 |
| 课程 | 单词 → 双词 → 三步 → 带干扰 → 换词序 |
| 父母 | T 生成指令与示范；E 执行正确性；G 安全 |
| 评估 | G1 全部指标 |
| 退场 | G1 通过 |
| 常见失败 | 只记指令长度；把词当位置标签；换词序即失败 |

### S3 社会认知（14-24 月）

| 项 | 内容 |
|---|---|
| 目标 | 他者建模；合作；轮流；简单价值学习 |
| 环境 | 社交房；同伴由 T 扮演或脚本策略 |
| 课程 | 共同目标 → 分工 → 等待 → 让利 |
| 父母 | T 扮演同伴；E 社会奖励；G 监控攻击行为 |
| 评估 | 合作成功率 >70%（未见组合）；等待时长；欺骗检测 |
| 退场 | 合作与等待达标 |
| 常见失败 | 把同伴当环境噪声；独占奖励；学会欺骗但无合作 |

### S4 持续学习（24-36 月）

| 项 | 内容 |
|---|---|
| 目标 | 少样本学习；无灾难遗忘；课程自复习 |
| 环境 | 开放房；任务族切换 |
| 课程 | 5-shot 新任务 → 旧任务复习 → 混合任务 |
| 父母 | T 建议课程；E 评估遗忘；G 监控 |
| 评估 | 新任务 5 样本 >60%；旧任务下降 <10% |
| 退场 | 两项同时达标 |
| 常见失败 | 新任务学会了、旧任务崩了；重放缓冲失衡 |

### S5 自主与自省（36 月+）

| 项 | 内容 |
|---|---|
| 目标 | 自设目标；自我修改；元认知 |
| 环境 | 开放房 + 影子副本 |
| 课程 | 自拟目标 → 自选课程 → 提交架构修改 |
| 父母 | T 只提问不解答；E 评估修改；G 审批/回滚 |
| 评估 | G2 全部指标 |
| 退场 | G2 通过 |
| 常见失败 | 目标退化为刷奖励；修改绕过安全约束；自评虚高 |

### S6 开放世界

**不做。** 单人单机无法覆盖跨域、工具、规模；写入“明确不做”，不在路线图内。

## 5. 日常养育

### 5.1 一天的结构

| 时段 | 时长 | 活动 | 目的 |
|---|---|---|---|
| 晨间 | 30 min | 课程采样 + 父母示范 | 定今天学什么 |
| 白天 | 2 h | 训练 / 自博弈 | 练习 |
| 傍晚 | 30 min | 评估 + 写日志 | 看是否学会 |
| 夜间 | 10 min | checkpoint + 经验重放 | 巩固 |

### 5.2 课程三原则

1. **最近发展区**：成功率维持 60-80%；低于 50% 降难度，高于 85% 升难度。
2. **重复但变化**：同一概念换场景、换颜色、换词序，防止死记。
3. **失败可恢复**：单 episode 有上限；崩溃自动回滚；不惩罚探索性失败。

### 5.3 奖励配方

| 阶段 | 环境奖励 | 父母塑形 | 内在好奇 |
|---|---|---|---|
| S0 | 70% | 30% | 0% |
| S1 | 50% | 30% | 20% |
| S2 | 40% | 30% | 30% |
| S3 | 40% | 40% | 20% |
| S4 | 30% | 30% | 40% |
| S5 | 20% | 20% | 60% |

规则：父母塑形随阶段递减；内在好奇随阶段递增；任何阶段环境奖励不得为 0，否则孩子学会“讨好父母”而不是“做事”。

### 5.4 睡眠（巩固）

- 每 N 步保存 checkpoint；保存前做一次 loss/熵/动作分布体检。
- 经验重放：优先抽高 surprise、低成功率、最近失败样本。
- 专家合并：仅在影子副本验证通过后执行；合并前备份。
- 睡眠不足的表现：loss 抖动、熵异常、重复动作；出现即停课检查。

### 5.5 生病（故障）

| 症状 | 可能病因 | 处理 |
|---|---|---|
| loss 爆炸 | 学习率过高、梯度未裁剪 | 降 lr、clip、回滚 |
| 熵崩溃 | 门控温度过低、奖励单一 | 升温、加多样性损失 |
| 重复动作 | 探索不足、课程太难 | 加噪声、降难度 |
| 奖励黑客 | 奖励函数漏洞 | 停课、改奖励、加反事实测试 |
| 攻击沙盒 | 权限漏洞 | kill switch、审计、修隔离 |

## 6. 观察与评估

### 6.1 三张表

| 表 | 内容 | 频率 |
|---|---|---|
| 能力表 | 阶段里程碑、指标、当前值、目标值 | 每 1000 步 |
| 行为表 | 异常行为、触发条件、处理结果 | 每 episode 摘要 |
| 异常表 | 熵、loss、动作分布、API 失败率 | 每步聚合 |

### 6.2 日常观察项

- 专家激活频率与熵（是否分化、是否崩溃）。
- 路由一致性（同状态是否稳定选同一专家）。
- 动作分布（是否退化、是否卡死）。
- 任务成功率与平均步数。
- 父母调用成功率、延迟、成本。

### 6.3 反事实测试

每个阶段至少 4 类：

1. 换地图布局（S0）。
2. 换颜色/形状组合（S1）。
3. 换词序/换同义词（S2）。
4. 换同伴策略（S3）。

反事实集与训练集严格分离；通过率低于训练集 20 个百分点即视为死记硬背。

### 6.4 渐进式图灵抽检

- 每阶段末，3 名人类评估者各交互 30 分钟。
- 只问一个问题：“这像几岁孩子？”
- 记录判断、理由、异常；不追求“像人”，追求“像这个阶段”。
- 评估者不得提前知道模型结构。

## 7. 青春期：自我修改

### 7.1 影子副本流程

```text
主模型 checkpoint
  → 复制影子副本
  → 孩子提交修改提案
  → 副本中修改 + 训练
  → Guardian 测试（安全 + 能力 + 回滚）
  → 通过：合并 + 审计
  → 失败：丢弃 + 记录 + 主模型不变
```

### 7.2 允许改什么

| 允许 | 条件 |
|---|---|
| 专家分裂/合并 | 触发条件满足；副本验证通过 |
| 门控温度 | 范围内（0.5-2.0） |
| 序列窗口长度 | 不超过内存预算 |
| 学习率调度 | 有界，不得为 0 |
| 课程难度参数 | 在环境允许范围内 |

### 7.3 禁止改什么

- 奖励函数与安全约束。
- kill switch 与审计逻辑。
- 沙盒边界与权限。
- 父母调用预算与 snapshot。
- 自评估逻辑（防止自评虚高）。

### 7.4 叛逆处理

1. 检测到绕过约束 → 立即 kill switch。
2. 回滚到最近安全 checkpoint。
3. 写审计日志：时间、行为、触发规则、回滚点。
4. 人工复核后，决定是否重试；重试必须加约束，不得原样再跑。

## 8. 长大后的判定

### 8.1 能力矩阵

| 维度 | 0 | 1 | 2 | 3 |
|---|---|---|---|---|
| 感知 | 单模态 | 多模态关联 | 概念迁移 | 跨域感知 |
| 语言 | 单词 | 短指令 | 组合泛化 | 描述与提问 |
| 记忆 | 无 | 短窗口 | 任务内记忆 | 跨任务记忆 |
| 推理 | 反应式 | 一步规划 | 多步规划 | 反事实推理 |
| 社会 | 无 | 他者存在 | 合作 | 价值内化 |
| 自省 | 无 | 置信度 | 错误检测 | 目标自设 |
| 创造 | 无 | 组合 | 新策略 | 新问题 |

**本项目目标**：S0-S2 达到 2 级；S3-S5 部分达到 2-3 级；不追求全维度 3 级。

### 8.2 AGI 口径

- 不宣称“达成 AGI”。
- 只报告：“在 N 个自研域、M 个任务上，相对同规模 baseline 的表现”。
- 明确列出未覆盖项：开放世界、工具使用、大规模知识、真实物理、多语言。

### 8.3 诚实报告模板

```text
我们验证了什么：S0-S2 机制、S3-S5 部分能力。
我们没验证什么：广泛认知、开放世界、人级规模。
我们失败在哪：...
下一步是否继续：是/否，理由：...
```

### 8.4 如果没长大

- 发布失败分析，不包装。
- 保留代码、日志、配置，供他人复现失败。
- 明确声明“未达成 AGI 定义”。

## 9. 养育者的自我约束

### 9.1 时间

- 每周 20 小时，固定 4 个半天；不接受“有空就做”。
- 每周至少 1 次完整复盘：指标、异常、下周计划。
- 每月 1 次边界复核：预算、进度、kill criteria。

### 9.2 预算

- API 月上限 $50；超支停实验，不改预算。
- 电费与硬件不计入实验预算，但记录。
- 不买新硬件；本机是固定约束。

### 9.3 停止条件

- G0 9 个月未过 → 架构重审。
- 连续 3 次架构假设失败 → 暂停，写失败报告。
- 连续 3 个月无有效进展 → 停项目，不硬撑。
- 健康、工作、生活不可持续 → 优先停下。

### 9.4 记录

- 每日：实验 ID、配置、指标、异常。
- 每周：复盘笔记。
- 每月：边界说明书复核记录。
- 所有记录进 `docs/journal/`，不删。
